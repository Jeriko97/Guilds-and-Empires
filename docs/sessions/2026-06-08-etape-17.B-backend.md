### TD-004 — Résiduel préservé dans lastProcessedAt

**Bug :** `lastProcessedAt = now` discardait le temps résiduel (elapsed modulo durationMs)
à chaque appel. Drift défavorable au joueur, jamais exploitable en Phase 1.

**Fix — double changement indissociable :**

1. `lastProcessedAt = createTimestamp(reference.toMillis() + completedCycles * durationMs)`
   — le résiduel est préservé pour le cycle suivant.

2. Détecteur d'écriture `if (updatedSlots !== now)` (identité d'objet) → brisé par le fix
   (nouveaux Timestamps construits via `fromMillis` ne sont jamais `=== now`). Remplacé par
   flag explicite `hasProcessedCycles: boolean` dans `ProcessBuildingResult`.

**Factory injection :** `createTimestamp: (ms: number) => firestore.Timestamp` injectée
comme 4e paramètre de `processBuildingSlots` — helper reste pur (pas d'`import * as admin`),
la factory est fournie par le call site (`collectProduction.ts`, `resolveLoginState.ts`).

**Option B confirmée :** `lastProcessedAt` avance de N cycles calculés sur le temps écoulé,
indépendamment du yield effectif (même si `actualYield = 0` par saturation cap).

3 tests dédiés ajoutés (8, 9, 10) :
- Test 8 : 1 cycle exact, résiduel nul
- Test 9 : N cycles + résiduel — preuve directe du fix
- Test 10 : inventaire saturé, Option B perte sèche

Commit : `4b7d66a`. 207/207 verts, 2 cycles à froid.
